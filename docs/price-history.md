# USD価格履歴

## 正規データ

履歴はSteamのUSD市場スナップショット（AppID `5084200`）だけから生成します。JPY価格、為替レート、換算結果は履歴JSONに含めません。各点は次の形式です。

```json
{
  "observedAt": "2026-10-25T03:00:00.000Z",
  "priceCents": 123,
  "listings": 4
}
```

価格は整数セント、出品数は整数です。USD価格または出品数を取得できない商品は記録しません。価格欠損を0として保存せず、空の市場スナップショットから履歴を作りません。

## 商品IDとファイル

`public/history/index.json`は`marketHashName`と商品ファイルIDの対応表です。IDは`marketHashName`のSHA-256小文字hex 64文字で、元の日本語や記号をパスに含めません。

各商品の時系列は`public/history/<sha256>.json`に保存します。画面は一覧を読み込む際に小さなindexだけ読み、商品名を押したときに該当商品のJSONだけを遅延取得します。

履歴点は`observedAt`の昇順で保存します。同一日時・同一価格・同一出品数の再実行は重複を追加しません。同一日時で内容が異なる場合は履歴更新全体を拒否します。価格や出品数が同じでも取得日時が異なれば別の観測点です。

## 追記・公開

`node scripts/steam-market.mjs --live`は従来の両通貨収集を実行し、両キャッシュが検証できた後にUSDスナップショットから履歴更新を準備します。市場JSONと履歴のすべてを一時ファイルに書き、検証後にまとめて反映します。いずれかの書き込みで失敗した場合は、変更済みファイルをロールバックします。

現在の取得は一対の市場キャッシュとして扱うため、SteamのUSD取得、JPY検証、必要な為替取得のどれかが失敗した場合、USD履歴も含めて更新しません。これは部分的な成功として古い市場表示と新しい履歴を混在させない判断です。履歴追加はGitHub Actionsの既存`workflow_dispatch` live jobに含まれます。定期Steam取得は有効化しません。

Actionsは`public/market-jpy.json`、`public/market-usd.json`、`public/history/`を一緒にステージし、変更の有無を判定します。為替更新Actionsと同じ`market-data-refresh` concurrency groupを使用し、並行Pushを防ぎます。

## グラフ・為替換算

履歴グラフは7日、30日、全期間で観測点を絞り、点の時刻を横軸、価格を縦軸に使います。観測点だけをSVGで描画し、補間データは追加しません。点はマウスホバー、タップ、キーボードフォーカスで日時・価格・出品数を確認できます。履歴JSONは商品詳細を開いたときだけ読みます。

USDは常にセントから表示します。JPYを選んだ場合、閲覧時に有効な`public/fx-rate.json`の最新レートを**全履歴の全点に同一適用**します。

```text
JPY参考価格 = Math.round(priceCents × 最新USD/JPYレート / 100)
```

過去時点の為替レートは使いません。レートが欠損・不正・期限切れの場合、JPYグラフだけを隠して理由を表示し、USDグラフは引き続き使えます。直接取得したSteamのJPY価格も履歴の基準には使いません。

## データ増加と復旧

1商品につき1ファイルに分け、一覧画面では履歴全体を取得しません。履歴が増えた場合もまず商品ファイル単位で配信を続けます。単一商品ファイルが大きくなりビルドまたは転送に影響する段階で、年単位の分割とindexの移行を検討します。データ保持期間を設ける場合は価格点の削除方針を明記してから実施します。

`npm run market:validate`は両市場キャッシュと履歴index・全履歴JSONの構造、AppID、商品対応、時刻順、値の型を検証します。検証失敗時はPushされません。破損したファイルを特定したら、Git履歴から最後の正常版を復元して検証コマンドを再実行してください。必要な場合は不正コミットを`git revert`し、Cloudflare Pagesで復旧デプロイを確認します。

過去データがまだない商品は「価格履歴はまだありません」と表示します。テストfixtureは`tests/`以下に隔離し、`public/history/`へ架空の観測点を置きません。
